# ResearchFlow

**연구자와 함께 작성하고 지속적으로 갱신하는 연구명세서 스킬**

[English](README.md) · [설치 안내](docs/installation.md) ·
[강의용 설명](docs/lecture-notes.ko.md) · [검토 결과](docs/review-report.md)

ResearchFlow는 연구자와 AI가 논의·확인하면서 **연구명세서 작성 및 갱신까지**
진행하는 범용 Agent Skill입니다. 코호트 연구에 한정하지 않고 머신러닝, 실험,
정성·이론 연구 등 다양한 연구 유형에 적용하도록 설계했습니다.

중심은 **Scientist-in-the-Loop와 Agile Research Specification**입니다.
논문 Reverse Engineering은 2단계의 중요한 기능이지만 전체 프레임워크의 중심은 아닙니다.

## 확정된 5단계

| 단계 | 명칭 | 주요 내용 |
|---|---|---|
| 1 | Research Framing | 연구 의도·질문·목적·범위 정의 |
| 2 | Literature Discovery & Workflow Reconstruction | 선행논문 선정, 실제 보고된 연구 흐름 재구성, 적용 가능성 검토 |
| 3 | Data & Resource Co-design | 데이터·변수·자료·자원 정의, 확보 가능성, 수집 계획 |
| 4 | Methodology & Evaluation Design | 방법론, 수행 절차, 비교·검증·평가 계획 |
| 5 | Specification Review & Baseline Approval | 명세 정합성 검토, 조건 확인, 승인된 기준 버전 보존 |

각 단계에서 **제안 → 근거·대안 검토 → 연구자와 논의 → 명시적 확인 → 명세 갱신**을
반복합니다. 단계의 명칭과 순서는 유지하되, 연구 내용은 새 근거와 제약에 따라 수정합니다.

## 주요 안전장치

- 연구자 승인, 근거 확인 수준, 데이터 확보 상태를 서로 구분합니다.
- 논문에 미보고된 내용과 접근하지 못한 내용을 구분하고 추측을 사실로 쓰지 않습니다.
- 데이터 확보 실패 시 대체 자료를 임의로 쓰지 않고 영향 분석과 수정 승인을 거칩니다.
- 승인한 내용 또는 그 전제가 변경되면 관련 단계에 재확인을 요구합니다.
- 이전 승인본을 덮어쓰지 않습니다. 사후 변경은 결과를 본 시점도 기록합니다.

실제 데이터 수집·가공·분석, 모델 학습, 실험·시뮬레이션 실행, 분석 코드 생성,
논문 결과 작성은 범위 밖입니다. 보조 Python 도구는 문서·승인 기록·버전 관리만 합니다.

## 설치 및 시작

소스 디렉터리에서 실행합니다. Python 보조 도구는 3.10 이상, 표준 라이브러리만 사용합니다.

```bash
python tools/install_skill.py --target claude
# 또는
python tools/install_skill.py --target codex
```

Claude Code에서는 `/researchflow`, Codex에서는 `$researchflow`로 호출합니다.
기존 설치가 있으면 덮어쓰지 않습니다. 커스텀 스킬 업로드를 지원하는 서비스에는
별도 `researchflow-skill-0.1.0.zip`을 사용합니다. 업로드 가능 여부와 자동 호출은
호스트·계정 정책에 따라 달라지며, 모든 채팅에서 설치된다고 가정하지 않습니다.

시작 프롬프트:

> ResearchFlow로 연구명세서를 함께 만들자. 연구 질문은 […]이고 현재 확보한 자료는 […]야.
> 기존 대화의 결정사항을 먼저 확인하고, 단계별로 핵심 결정을 나에게 확인받아줘.
> 실제 분석은 실행하지 마.

변경 요청:

> 계획했던 데이터가 확보되지 않았어. 기존 승인본은 유지하고, 연구 질문·방법·평가에
> 미치는 영향을 분석한 뒤 대안을 제시하고 수정 승인을 받아줘.

## 검토 범위와 한계

자동 테스트는 상태 관리, 승인 기록의 내용 일치, 변경 후 재확인, 스냅샷 보존,
설치·패키징 등을 검사합니다. 과학적 타당성이나 실제 Claude/Codex의 행동을
보증하지는 않습니다. 실제 모델 평가용 시나리오는 별도 제공하며 실행 여부는
[검토 보고서](docs/review-report.md)에 구분해서 기록합니다.

GitHub 게시 여부는 패키지 생성과 별개의 상태입니다. 게시용 계정·쓰기 경로가
준비되면 [게시 안내](docs/publishing.md)의 명령으로 저장소와 릴리스를 만들 수 있습니다.
